# Agent 节点与流程编排

## 使用方式

左侧栏在「AI 创作」之后依次新增「Agent 节点管理」「Agent 流程编排」，后面是「提示词管理」。

1. 在「提示词管理」维护提示词，或导入 GitHub Skills。
2. 打开 `/agent-nodes`，新建节点，填写名称、说明、输出类型，并选择关联的提示词或 Skills。可以查看关联内容详情和调整应用顺序。
3. 打开 `/agent-workflows`，新建流程，依次添加节点，通过上移、下移、移除调整链条。一个流程最多 10 步，允许重复使用同一节点。
4. 点击流程的「运行」，填写本次任务要求和输入素材。任务由 `ai-worker` 后台执行，关闭页面不会中止运行。
5. 在「运行记录」查看每个节点的状态、结果、耗时、重试次数和运行时的提示词快照。

例如，可以创建「文章生成」「文章审核」「文章修订」三个节点，编排为：

```text
本次要求与原始素材 → 文章生成 → 文章审核 → 文章修订
```

文章修订节点会收到原始要求、生成的文章和审核意见。审核之后还需要再审核时，可以把同一个审核节点再次添加到链条末尾。

## 节点输出类型

| 类型 | 输出 | 用途 |
| --- | --- | --- |
| 文本处理 | `text` | 分析、提纲、总结等 |
| 文章生成 / 修订 | `title`、`content`、`excerpt` | 生成完整文章，或结合前序意见修订 |
| 文章审核 / 评分 | `score`、`decision`、`summary`、`issues`、`suggestions` | 0～100 分，结论为通过、建议修改或不通过 |

每个节点至少关联一项提示词或 Skill，最多 20 项。具体的写作要求、评分维度和通过标准由关联内容规定。

这版按固定顺序执行。审核结论会传给后续节点，但不会自动跳转、循环修订或触发平台发布。「执行完成」表示节点均成功输出，不等于审核通过。

## 文章与内容流联动

- `/articles` 每篇文章的「Agent 流程」按钮：将文章当前版本作为来源，启动审核或修订流程。「流程记录」可查该文章作为输入或流程输出的运行。
- `/tweets` 的 AI 生成弹框：点击「选择 Agent 流程」，以当前内容作为来源启动流程。
- 流程完成且存在文章节点时，可以点击「保存新草稿到文章管理」。保存最后一个文章节点的完整输出；后面的审核结果保留在运行记录中。
- 保存会新建未发布草稿，重复点击返回同一篇草稿。原文章继续保留。来源文章发生变化时，运行详情会提示结果基于旧版本。
- `/ai-writing` 监听任务继续使用现有生成链路；本次新增的流程通过流程页面、文章管理或内容流手动启动。

## 服务职责与上下文

- `backend`：节点、流程、运行记录 API 和快照创建。
- `skill-worker`：继续通过既有 Nacos 发现及 HTTP 接口提供提示词与 Skills 解析；创建运行时一次性解析并固定全部内容。
- `ai-worker`：从数据库领取流程任务，按顺序调用现有 AI 数据源，与文章生成、智能体对话共享并发限制。

每一步模型调用使用 OpenAI Responses 协议：

- `instructions`：节点职责、输出要求、关联的提示词和 Skills。
- `input`：本次任务要求 `task`、原始来源 `source`、全部前序结果 `previous_steps`。
- `text.format`：按节点类型约束 JSON 输出，再由服务端校验。

前序结果包含节点序号、名称、类型和结构化输出，后续节点无需重新查询文章或提示词。当前运行只处理文字，不执行 Skills 仓库内的脚本或外部工具。

运行保存流程、节点、提示词版本和模型参数快照。后续编辑或停用配置不会改变既有运行。API Key 不进入快照；允许轮换密钥。数据源地址、协议或模型变化后，旧运行会明确报错，需按新配置重新启动。

## 状态与恢复

流程状态包括排队、执行、等待重试、完成、失败、取消。每完成一个节点就持久化一次结果；Worker 重启或租约过期后，从尚未完成的节点继续。可重试错误最多自动尝试 3 次，最终失败后可以手动重试，已成功节点保持原结果。

取消会使执行租约失效，迟到的模型响应不会写入。已经发给模型的请求可能仍在上游完成。为避免上下文无限增长，单节点关联指令最多 160,000 字符，输入上下文最多 200,000 字符，超过后明确报错。

节点和流程使用停用方式保留历史。停用节点会阻止依赖它的流程发起新的运行。编辑启用开关可以恢复使用。

## 数据库和上线

迁移 `0042_agent_workflows` 新建五张表：

- `ai_agent_nodes`：节点定义。
- `ai_agent_workflows`：流程模板。
- `ai_agent_workflow_steps`：流程节点顺序。
- `agent_workflow_runs`：运行快照、状态和文章关联。
- `agent_workflow_step_runs`：每一步的执行结果与尝试次数。

上线时先执行 `alembic upgrade head`，再更新 `backend`、`ai-worker` 和前端。此次不需要新增服务、修改 Nacos 注册配置或增加磁盘挂载。

测试 `backend/tests/test_agent_workflows.py` 使用隔离数据库和模拟模型响应，覆盖顺序与重复节点、版本冲突、上下文传递、快照隔离、幂等提交、失败恢复、取消、访问隔离、文章版本和草稿保存，以及迁移升级/回退。真实模型生成质量需要结合实际提示词另行验收。
