# 小红书接入与发布

X Sentinel 通过开源 `xpzouying/xiaohongshu-mcp` 连接小红书。该执行端使用浏览器自动化与扫码登录，不需要把小红书账号密码保存到 X Sentinel；Cookie 保存在 MCP 执行端自己的持久化目录。

## 启动 MCP 执行端

Docker 模式：

```bash
docker compose --profile xiaohongshu up -d xiaohongshu-mcp
```

本机二进制模式可从该项目的 GitHub Releases 下载与当前系统匹配的 `xiaohongshu-mcp`，启动后默认地址是 `http://127.0.0.1:18060/mcp`。生产环境建议给 MCP 设置 `AUTH_TOKEN`；在 X Sentinel 菜单中填写同一令牌。令牌只以密文写入 MySQL，Redis 只缓存密文。

## 管理台配置

1. 进入“小红书发布” → “连接与登录”。
2. 宿主机开发填写 `http://127.0.0.1:18060/mcp`；Docker Compose 内部填写 `http://xiaohongshu-mcp:18060/mcp`。
3. 保存后点击“获取登录二维码”，使用小红书 App 扫码，再执行“测试连接与登录”。
4. 在“发布策略”启用总开关，并选择手动、立即自动或延迟发布。
5. 在“新建文章”填写标题、正文、至少一张图片及可选话题；图片支持 HTTP(S) URL 或 MCP 容器内可读的绝对路径。

## 发布策略

- 手动：文章先保存为草稿，管理员在任务列表中点击发布。
- 自动：创建文章后立即进入 Worker 队列。
- 延迟：到指定时间后由 Worker 发布；默认延迟可在配置页调整。

Worker 使用 Redis 分布式锁和 MySQL 租约防止重复执行，失败会指数退避重试，并受每日发布上限控制。发布结果、尝试次数、错误和平台返回摘要会保留用于审计。

## 平台限制与风险

- 当前图文发布要求标题不超过 20 字、正文不超过 1000 字，并至少提供一张图片。
- 同一账号不要同时登录多个网页端，否则 MCP 的 Cookie 可能失效。
- 网页 DOM、验证码和平台风控可能随时变化；自动发布不代表能够绕过平台安全校验。
- 只发布原创或已获授权的内容，避免批量搬运、引流和高频操作。建议先以“仅自己可见”完成少量验证。
